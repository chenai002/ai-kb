# 11 · token、成本与限制

> 为什么 AI 按"字数"收费？为什么聊得越久越贵？为什么它记不住特别长的对话？
> 这篇把 AI 的"成本账单"说清楚。

---

## 一、先搞懂 token

### 1.1 什么是 token

**token 是模型处理文字的最小单位**，它不是字，也不是词。

```
"Hello world"     → ["Hello", " world"]       2 个 token
"人工智能"         → ["人工", "智能"]           2 个 token
"我是一个程序员"    → ["我是一个", "程序员"]      2 个 token
```

**粗略换算**：
| 语言 | 1 token ≈ |
| --- | --- |
| 英文 | 0.75 个单词（≈ 4 个字符） |
| 中文 | 1–2 个汉字 |
| 代码 | 2–3 个字符 |

### 1.2 为什么按 token 不按字

因为模型内部就是按 token 工作的：**它读的是 token，写的是 token，算力也花在 token 上**。
按 token 收费，最贴近真实成本。

---

## 二、钱花在哪：输入 token 和输出 token

### 2.1 两种 token 都收费

```
输入 token（你发给模型的）：
  - 系统提示
  - 历史对话
  - 你的问题
  - RAG 检索到的资料

输出 token（模型生成给你的）：
  - 回答内容
```

**关键：输出通常比输入贵得多**（一般是 3–5 倍）。
因为生成比读取更耗算力：读取可以并行，生成必须一个一个来。

### 2.2 一个真实账单的构成

假设一次对话：

```
系统提示：200 token
历史对话：3000 token          ← 越聊越多！
RAG 资料：5000 token
用户问题：50 token
                        输入合计：8250 token

模型回答：500 token           输出

价格（假设输入 $0.15/百万，输出 $0.60/百万）：
  输入：8250 × 0.15 / 1,000,000 = $0.0012
  输出：500  × 0.60 / 1,000,000 = $0.0003
  单次合计约 $0.0015（约 1 分钱）
```

看起来不多，但：
- 一天 1 万次调用 → 约 100 元/天
- 一个月 → 约 3000 元

### 2.3 对话越长越贵（重要）

因为**每次都要把历史对话重新发一遍**：

```
第 1 轮：输入 500 token
第 5 轮：输入 3000 token
第 10 轮：输入 6000 token
第 20 轮：输入 12000 token    ← 单次成本翻了 24 倍
```

**这就是为什么长对话很贵。**

**缓解办法**：
- 定期开启新对话
- 把历史压缩成摘要（"前情提要"）
- 只保留最近 N 轮

---

## 三、成本优化：六个实用手段

### 3.1 用对模型

```
简单任务（分类、提取、改写）→ 小模型，便宜 10–50 倍
复杂任务（推理、长文分析）→ 大模型
```

**大部分场景不需要最强的模型。**

### 3.2 控制上下文

| 手段 | 效果 |
| --- | --- |
| 裁剪历史对话 | 显著（长对话场景） |
| 精简系统提示 | 中等 |
| RAG 只取最相关的 3 段（而不是 20 段） | 显著 |
| 工具返回值精简 | 中等 |

### 3.3 缓存（Prompt Caching）

很多平台支持"相同前缀的输入"缓存：

```
你的系统提示 + 公司资料（每次都一样）
→ 第一次全价，之后打折（通常省 50%–90%）
```

**适用**：固定的大段系统提示、固定的知识库内容。

### 3.4 控制输出长度

```
❌ "详细分析一下"
✅ "用 3 点说明，每点不超过 50 字"
```

输出比输入贵，**控制输出是最直接省钱的方式**。

### 3.5 批处理

不需要实时响应的任务（如批量给商品打标签）：
- 用批处理接口（通常打 5 折）
- 或者离线跑

### 3.6 别让 Agent 无限循环

Agent 每循环一轮就多一次完整调用（+ 不断增长的上下文）。
**必须设置步数和预算上限**（见第 07 篇）。

## 四、限制：不只是钱

### 4.1 上下文窗口（Context Window）

**一次能处理的 token 总数上限。**

| 模型 | 常见窗口 |
| --- | --- |
| 早期模型 | 4K–8K |
| 现在的主流 | 128K–200K |
| 超长上下文模型 | 1M+ |

**超出会怎样**：
- 要么报错
- 要么自动截断最早的内容（导致"忘事"）

**注意**：窗口大不代表都用得好。**"能装下"和"能用好"是两回事**——长文档中间的内容容易被忽略（叫"lost in the middle"）。

### 4.2 速率限制（Rate Limit）

平台对**单位时间内**的请求数和 token 数有限制：

| 类型 | 含义 |
| --- | --- |
| **RPM** | 每分钟请求数 |
| **TPM** | 每分钟 token 数 |
| **RPD / TPD** | 每天的上限 |

**超限会返回 429 错误**（Too Many Requests）。

**应对**：
- 指数退避重试
- 申请更高配额
- 分散到多个模型/账号
- 本地排队削峰

### 4.3 并发限制

同一时间能进行的请求数有限。高并发场景（如批量处理）要注意错峰。

## 五、一笔钱的完整账（企业视角）

假设你做一个客服助手，日均 1 万次对话：

| 项目 | 估算 |
| --- | --- |
| 平均每次输入 | 2500 token（含系统提示、历史、RAG） |
| 平均每次输出 | 300 token |
| 单次成本（中档模型） | 约 ¥0.01 |
| 日均 1 万次 | 约 ¥100 |
| 月成本 | 约 ¥3,000 |
| 年成本 | 约 ¥36,000 |

**如果换成大模型**（贵 10 倍）：年成本 36 万。
**如果做优化**（裁剪历史 + 小模型处理简单请求）：可能降到 1/3。

**所以成本优化的收益非常可观。**

## 六、常见困惑

**Q：为什么我发一段长文字，它说超出限制？**
因为你的输入 + 要生成的输出，加起来超过了上下文窗口。

**Q：输入和输出分别怎么计费？**
大部分平台分开计价，输出更贵。具体看平台文档。

**Q：中途取消会退钱吗？**
通常**已经生成的部分会计费**，哪怕你关闭了页面。

**Q：缓存能省多少？**
一般能省 50%–90%（取决于平台），前提是前缀完全相同。

**Q：为什么同一个问题，两次费用不同？**
因为输出长度不同（模型每次生成的字数可能不一样）。

**Q：本地跑模型是不是免费？**
不是免费，但边际成本接近 0。代价是：
- 要自己买 GPU（几万元起）
- 要自己运维
- 效果可能不如闭源大模型

**什么时候自建划算**：调用量很大（月成本超过几万元）、数据敏感、需要定制。

---

## 七、几个容易忽略的隐性成本

| 隐性成本 | 说明 |
| --- | --- |
| **重试** | 失败的请求通常也要计费 |
| **Agent 循环** | 一个任务可能触发 10–20 次调用 |
| **向量化** | RAG 建库时，每段文档都要算 embedding（也按 token 收费） |
| **评估** | 跑测试集也是调用模型 |
| **日志与存储** | 存对话记录、向量库的存储费 |

---

## 八、用一句话解释给朋友听

> 「AI 按 token 收费，token 大约半个词。每次对话都要把之前的所有内容重新发一遍，所以聊得越久越贵。省钱的办法是：用合适的模型、别把无用内容塞进去、控制回答长度，别让 Agent 无限循环。」
