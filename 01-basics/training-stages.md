# 03 · 训练三阶段：一个"野路子"模型怎么变成好助手

> 刚训练完的模型就像一个读遍全世界的书呆子：什么都知道一点，但不会好好说话，也不一定听你的。
> 把它变成 ChatGPT 那样的助手，要经过三个阶段。

---

## 一、总览

```
阶段一：预训练（Pre-training）
   读海量文本，学会"语言是什么"
   → 产物：基座模型（Base Model）
   → 特点：只会续写，不会对话，可能胡说

   ↓  成本：最高（几千张 GPU 跑几个月，上千万美元）

阶段二：监督微调（SFT）
   看人类写的"问答示范"，学会"怎么回答"
   → 产物：指令模型（Instruct Model）
   → 特点：会对话了，但回答质量参差

   ↓  成本：中等（几万条高质量问答）

阶段三：人类反馈强化学习（RLHF）
   根据人类偏好排序，学会"什么是好回答"
   → 产物：对齐模型（Aligned Model）= ChatGPT
   → 特点：更有帮助、更诚实、更安全

   ↓  成本：高（需要人类标注 + 强化学习）

可选阶段四：持续迭代
   新数据、新能力、新版本
```

---

## 二、阶段一：预训练

### 2.1 在做什么

**任务**：给模型看一段文字，让它猜下一个词。

```
输入： "床前明月"
目标： 模型应该输出 "光"
```

就这么简单。但是：
- 数据量：几万亿个 token（相当于把维基百科读几十万遍）
- 参数规模：几十亿到上万亿
- 算力：几千张 GPU 连续跑几个月

### 2.2 学到了什么

为了"猜得准"，它被迫学会了：
- **语法**：什么样的词序是合法的
- **常识**：太阳从东边升起
- **知识**：历史、地理、科学
- **推理模式**：因为 A 所以 B
- **代码**：编程语言的规律

### 2.3 产物：基座模型

特点：
- ✅ 语言能力很强
- ✅ 知识量大
- ❌ **不会对话**：你问"你好"，它可能续写"你好，请问有什么…"也可能直接写一段小说
- ❌ **不听指令**：让它"总结一下"，它可能写一篇关于总结的文章
- ❌ **不安全**：会输出有害内容（因为训练数据里有）

**比喻**：一个读遍图书馆但没上过班的人。

### 2.4 数据从哪来

| 来源 | 占比（大致） | 说明 |
| --- | --- | --- |
| 网页（Common Crawl） | 大头 | 质量参差，需要清洗 |
| 书籍 | 中等 | 质量高、长文本 |
| 代码（GitHub） | 中等 | 提升推理能力 |
| 百科、论文 | 较少 | 高质量知识 |
| 对话数据 | 较少 | 需要爬取或合成 |

**数据质量 > 数据数量**，这是近年共识。

## 三、阶段二：监督微调（SFT）

### 3.1 在做什么

给模型看**人类写的示范对话**：

```
用户：帮我用一句话解释什么是黑洞
助手：黑洞是引力强到连光都逃不出来的天体。
```

这种"问答对"准备几万到几十万条，继续训练模型。

### 3.2 学到了什么

学会了**"对话格式"**：
- 看到「用户：xxx」，应该续写「助手：yyy」
- 回答要简洁、有帮助、有礼貌
- 拒绝不合适的要求

### 3.3 产物：指令模型

特点：
- ✅ 会对话了
- ✅ 能听懂"总结一下""翻译成英文"这类指令
- ⚠️ 回答质量取决于示范数据
- ⚠️ 遇到示范里没有的情况，可能表现不佳

**比喻**：图书馆里的书虫，被安排师傅带了三个月，学会了怎么接待客人。

### 3.4 为什么叫"监督"

因为每条数据都有"标准答案"（人类写的），模型照着学。这叫有监督学习。

## 四、阶段三：RLHF（人类反馈强化学习）

### 4.1 为什么需要它

SFT 有个问题：**"标准答案"只能教你"该说什么"，教不了"哪个更好"。**

对比：
```
问题：地球为什么是圆的？

回答 A：因为引力使物质向中心聚集，形成近似球体。（准确但干巴巴）
回答 B：想象一下，如果地球是方的，边角处的引力会把它拉向中心…
        （生动、易懂，但没有 A 精确）
```

哪个更好？**取决于场景**。SFT 没法表达"偏好"，RLHF 可以。

### 4.2 怎么做的（三步）

**第一步：收集人类偏好**

给标注员看同一个问题的多个回答，让他们排序：

```
问题：如何学好编程？

回答 A：多写代码。
回答 B：先从简单的语言开始，每天写小项目，遇到问题先自己查文档，
       再问人。坚持三个月你会有明显进步。

标注员：B 更好 ✓
```

**第二步：训练一个"打分模型"（Reward Model）**

用人类排序数据训练一个模型，学会"什么样的回答得分高"。

**第三步：用打分模型来优化主模型**

主模型生成回答 → 打分模型打分 → 主模型根据分数调整 → 循环。

用算法（如 PPO）让模型更倾向生成高分回答。

> 现代的做法改进版叫 **DPO**（直接偏好优化），原理不同但目标一样：让模型学会人类偏好，且更简单。

### 4.3 产物：对齐模型

特点：
- ✅ 更有帮助（有用、详细、有条理）
- ✅ 更诚实（更倾向承认不知道）
- ✅ 更安全（拒绝有害请求）
- ⚠️ 可能"过度对齐"：变得过于谨慎、爱说套话

**比喻**：书虫经过师傅指导后，又做了半年客服，学会了"客户想要什么"。

### 4.4 "对齐"到底是什么意思

**对齐（Alignment）**：让 AI 的行为符合人类的价值和意图。

三个方面（被称为 HHH）：
- **Helpful**（有帮助）：真的解决问题
- **Honest**（诚实）：不知道就说不知道
- **Harmless**（无害）：不造成伤害

## 五、三个阶段对比

| | 预训练 | SFT | RLHF |
| --- | --- | --- | --- |
| 学什么 | 语言规律与知识 | 对话格式 | 人类偏好 |
| 数据 | 几万亿 token | 几万条问答 | 几万条偏好排序 |
| 算力 | 极高 | 低 | 中 |
| 谁来做 | 大厂 | 大厂/有资源团队 | 大厂 |
| 产出 | 基座模型 | 指令模型 | 助手模型 |

## 六、还有哪些"调教"手段

### 6.1 思维链（Chain-of-Thought）

**做法**：训练模型在回答前先写出推理步骤。

```
问题：一个班 30 人，60% 是女生，女生里 1/3 戴眼镜，多少人戴眼镜？

不写步骤：6 人（可能是猜的）
写步骤：30 × 60% = 18 个女生；18 × 1/3 = 6 人戴眼镜。答案：6 人。
```

**为什么有效**：把中间结果写进上下文，模型下一步可以参考（见第 02 篇"为什么算术会错"）。

**现在的推理模型**（如 o1 系列）就是把"先想再答"做成默认行为，甚至"想"很久。

### 6.2 指令微调 vs 少样本学习

| 方式 | 做法 | 成本 |
| --- | --- | --- |
| 微调 | 用你的数据改模型参数 | 高，需要训练 |
| 少样本（Few-shot） | 在提示词里给几个例子 | 零，改提示词就行 |
| RAG | 把资料塞进上下文 | 低，见第 06 篇 |

> **小白记住**：大多数需求，改提示词或加 RAG 就够了，不必微调。见第 09 篇。

## 七、常见困惑

**Q：模型会从我的对话里学习吗？**
不会（默认情况下）。训练是离线批量做的。你的对话除非被特别用于改进（很多产品会让用户选择），否则不进训练。

**Q：为什么不同公司的模型能力差异这么大？**
数据质量、训练方法、算力规模、对齐策略都不同。

**Q：开源模型为什么"弱"一些？**
不一定弱。开源模型往往在算力或数据上受限，但在特定任务上可以很接近甚至超过闭源。

**Q：为什么模型有时会"过度拒绝"？**
RLHF 让它在安全上更保守，有时会误判。这是对齐的副作用。

**Q：能自己训练一个吗？**
预训练基本不可能（成本）。但**微调是可以的**，见第 09 篇。

## 八、用一句话解释给朋友听

> 「模型分三步炼成：先读遍全世界的书学会说话（预训练），再看人类的问答示范学会对话（SFT），最后根据人类觉得哪个回答更好来调整（RLHF）。所以它既有知识，又懂礼貌，还知道该拒绝什么。」
