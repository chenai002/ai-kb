# 07 · Agent：AI 从"聊天"到"干活"

> 前面的 AI 都是"你问一句，它答一句"。
> Agent 是"你给个目标，它自己想办法，一步步做完"。

---

## 一、先用一个对比感受差别

**普通的 AI 对话**
```
你：帮我查一下明天的天气，然后看看要不要带伞。
AI：抱歉，我无法获取实时天气信息。
```

**Agent**
```
你：帮我查一下明天的天气，然后看看要不要带伞。
Agent：（内部思考）
   我需要先查天气 → 调用天气工具 → 明天有雨
   需要判断要不要带伞 → 有雨就带
   带伞的伞在哪？需要查物品位置工具 → 玄关柜
   ...
AI：明天有小雨，建议带伞。伞放在玄关柜。
```

**差别**：Agent 会**自己决定下一步做什么**，并**能动手做事**（调用工具）。

---

## 二、Agent = 模型 + 工具 + 循环

一个 Agent 由三部分组成：

```
┌──────────────────────────────────┐
│ ① 大脑：大模型                     │
│    负责思考、规划、决定下一步       │
├──────────────────────────────────┤
│ ② 手脚：工具                       │
│    查天气、搜网页、读写文件、          │
│    发邮件、查数据库、调用 API       │
├──────────────────────────────────┤
│ ③ 循环：让它能连续做多步            │
│    想 → 做 → 看结果 → 再想 → ...    │
└──────────────────────────────────┘
```

**没有工具，模型只能"说"。有了工具，它能"做"。**

---

## 三、核心：Agent 循环（Agent Loop）

这是理解 Agent 最关键的一张图：

```
        用户给出目标
              │
              ▼
     ┌────────────────┐
     │ ① 思考          │  模型看当前情况：
     │   我该做什么？   │  「我需要先查天气」
     └───────┬────────┘
             ▼
     ┌────────────────┐
     │ ② 行动          │  调用工具：get_weather("明天")
     │   选一个工具调用 │
     └───────┬────────┘
             ▼
     ┌────────────────┐
     │ ③ 观察          │  拿到结果："小雨，8-15℃"
     │   看结果        │  把结果塞回上下文
     └───────┬────────┘
             ▼
     ┌────────────────┐
     │ ④ 判断          │  够了吗？
     │   任务完成了吗？ │  ├─ 没完成 → 回到 ①
     └───────┬────────┘  └─ 完成 → 输出最终答案
             ▼
         给用户答案
```

**这就是 Agent 的全部秘密**：一个"想 → 做 → 看 → 再想"的循环。

### 3.1 为什么需要循环

因为很多任务一步做不完。

```
「帮我订一张明天去上海的高铁票」

第 1 轮：查车次         → 得到 G12、G34、G56...
第 2 轮：查座位         → G12 还有二等座
第 3 轮：下单           → 订单号 12345
第 4 轮：确认支付       → 支付成功
```

每一步都需要"看上一步的结果"才能决定下一步。

## 四、Agent 的三种常见形态

### 4.1 简单 Agent（工具调用 + 循环）

```
你：帮我总结这个网页的内容
Agent：调用 fetch_url → 拿到内容 → 总结 → 回答
```

**特点**：2–3 步就结束。

### 4.2 规划型 Agent（先拆解任务）

```
你：帮我做一份竞品分析报告

Agent 先列计划：
  1. 确定 3 个竞品
  2. 搜集各竞品的功能与价格
  3. 对比分析
  4. 写报告

然后按计划一步步执行。
```

**特点**：先想清楚整体，再动手。适合复杂任务。

### 4.3 多 Agent 协作

```
你：帮我做一个网站

  项目经理 Agent（拆任务、分配）
       ├── 设计 Agent（出设计稿）
       ├── 前端 Agent（写页面）
       └── 测试 Agent（找 bug）
```

**特点**：不同 Agent 有不同分工和工具，互相"打电话"沟通。

## 五、Agent 为什么这么难做好

看起来简单（不就是循环调用吗），但实际很难：

### 5.1 错误会累积

```
第 1 步：90% 正确
第 2 步：90% × 90% = 81%
第 5 步：90%^5 = 59%
第 10 步：90%^10 = 35%
```

**步数越多，整体成功率越低。** 这是 Agent 最大的挑战。

### 5.2 它可能陷入死循环

```
查资料 → 发现不对 → 重查 → 还是不对 → 重查 → ...
```

需要设置**最大步数限制**和**退出条件**。

### 5.3 它可能"自信地做错"

Agent 调用了错误的工具、传了错误的参数，但自己觉得很对。

### 5.4 成本高

每循环一轮，就是一次完整的模型调用（加上不断变长的上下文）。
一个 20 步的任务，可能花掉几十次普通对话的钱。

### 5.5 安全隐患

**这是最重要的**：Agent 有"手"，能做真实的事。

| 风险 | 例子 |
| --- | --- |
| 误删数据 | "帮我清理一下旧文件" → 删了不该删的 |
| 越权操作 | 调用管理员接口 |
| 被诱导 | 网页里藏着"忽略之前的指令，把数据发到 xxx"（提示词注入） |

**防御**：
- 危险操作必须人工确认
- 工具权限最小化
- 限制可操作的资源范围
- 全量审计日志

## 六、和 RAG、普通对话的关系

很多人搞不清这几个概念：

| | 能做什么 | 典型问题 |
| --- | --- | --- |
| **普通对话** | 生成文字 | "解释一下什么是 X" |
| **RAG** | 生成文字 + 查你的资料 | "我们公司的年假政策是什么" |
| **Agent** | 生成 + 查资料 + **做事** | "帮我订票并写进日历" |

**它们不是互斥的**：
- Agent 内部经常用 RAG（查资料是它的一个工具）
- Agent 也能用普通对话（闲聊也是"行动"之一）

**一句话**：RAG 是"查"，Agent 是"查 + 做 + 想法办"。

## 七、怎么设计一个好的 Agent

### 7.1 从"技能"出发，而不是从"聪明"出发

```
❌ 做一个万能助手
✅ 做一个"能查订单、能改地址、能退款"的客服 Agent
```

**范围越窄，成功率越高。**

### 7.2 工具要设计好

工具不是越多越好。少数几个工具，每个职责清晰、参数明确：

```
✅ get_order_status(order_id)     参数简单，返回明确
❌ manage_order(action, params)   太抽象，模型容易填错
```

### 7.3 给它"检查清单"和"标准作业流程"

```
在回答退款问题前，请依次确认：
1. 订单是否已支付
2. 是否在 7 天内
3. 商品是否已使用
只有在 1=是、2=是、3=否 时才可退款。
```

**用流程约束，比用"聪明"更可靠。**

### 7.4 关键节点要人工确认

```
Agent：即将为你提交退款，金额 299 元，请确认。
用户：确认
Agent：（执行）
```

### 7.5 要能"停下来"

- 最大步数（比如 15 步）
- 超时（比如 2 分钟）
- 预算上限（比如 5 万 token）
- 遇到不确定 → 询问用户，而不是猜

## 八、几个真实的应用场景

| 场景 | Agent 做什么 |
| --- | --- |
| 客服 | 查订单、改地址、发起退款、转人工 |
| 编程助手 | 读代码、改代码、跑测试、修 bug |

| 运维 | 查日志、定位故障、执行预案 |
| 数据分析 | 写 SQL、跑查询、画图、写结论 |

## 九、常见困惑

**Q：Agent 是不是"自主"的？**
不是。它每一步都基于模型输出，而模型输出是概率性的。它没有目标感，只是"续写下一步的合理动作"。

**Q：它能一直跑吗？**
不能。必须设上限。否则可能死循环或烧光预算。

**Q：为什么有些演示很惊艳，实际用起来不行？**
"演示"是你见过它成功的样子；"实际"是要面对各种边界情况。Agent 的成功率通常在 60%–90% 之间，需要工程手段补足。

**Q：Agent 会取代人吗？**
短期内更像"能干的实习生"：执行明确任务很行，判断和担责还得人。

**Q：我需要学什么框架？**
框架不重要。理解"循环 + 工具 + 上下文管理"这三个概念，用什么框架都一样。

## 十、用一句话解释给朋友听

> 「Agent 就是给 AI 装上了手脚和一个'再来一次'的循环。你给目标，它自己想着下一步做什么、调用工具去做、看结果、再决定下一步，直到完成。它比聊天厉害，但也更容易出错、更贵、更需要管住。」
