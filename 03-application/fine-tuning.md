# 09 · 微调：让 AI 学会你们的说话方式

> 微调听起来很高大上，但它的适用场景其实很窄。
> 这篇帮你判断：**你到底该不该微调。**

---

## 一、先搞清三件事的区别

很多人把这三个混在一起：

| | 改什么 | 解决什么 | 成本 |
| --- | --- | --- | --- |
| **提示词** | 你每次输入的内容 | 让它在"这次任务"上做对 | 极低 |
| **RAG** | 提供给它的资料 | 让它知道你的"知识" | 低 |
| **微调** | 模型内部的参数 | 让它学会"怎么说话/怎么做" | 高 |

**一句话区分**：
- 提示词：**告诉它这次怎么做**
- RAG：**让它查到你的资料**
- 微调：**改变它的"肌肉记忆"**

---

## 二、微调到底在做什么

### 2.1 原理（简化）

微调就是"用你的数据，继续训练模型"。

```
预训练（读过全世界的书）
    ↓
微调（再用你的几百/几千条数据练一练）
    ↓
你的专属模型
```

**类比**：
一个大学毕业生（已经会读写思考），进你们公司做了两周岗前培训（微调），学会了你们公司的术语和流程。

**注意**：微调**不会**让它学到新的事实知识（文档内容），只会改变它的"行为模式"。

---

## 三、什么时候该微调（5 个信号）

### ✅ 信号 1：需要固定格式

```
要求：所有回复必须是这个格式
{
  "intent": "...",
  "entities": {...},
  "confidence": 0.95
}
```

提示词也能做到，但如果要 100% 稳定，微调更可靠。

### ✅ 信号 2：需要特定风格

```
让 AI 用你们品牌的口吻写文案
让 AI 模仿某位专家的分析框架
```

### ✅ 信号 3：需要"压缩"提示词

```
你的提示词有 3000 字（背景 + 规则 + 例子），
每次请求都带上 → 又贵又慢
微调后，直接省掉这 3000 字
```

### ✅ 信号 4：任务很窄但要求高

```
医疗病历结构化
法律合同条款抽取
工业质检报告生成
```

窄任务 + 高质量数据 → 微调效果往往超过通用大模型。

### ✅ 信号 5：需要小模型降本

```
用 70B 大模型做某任务，太贵太慢
→ 用 7B 小模型微调，专做这一件事
→ 效果好、成本低 10 倍
```

**这是企业微调最主要的动机。**

---

## 四、什么时候不该微调（4 个信号）

### ❌ 不该 1：只是想让它知道你的资料

```
"我想让它知道我们公司的规章制度"
```

→ **用 RAG**。微调学不会这些事实，而且每次制度更新都要重训。

### ❌ 不该 2：数据太少

```
只有 50 条样本
```

→ 微调效果很可能不如精心写提示词。**通常至少需要几百到几千条高质量样本。**

### ❌ 不该 3：任务经常变

```
业务需求每周都在变
```

→ 每次都要重新准备数据、训练、评估，成本太高。

### ❌ 不该 4：还没试过提示词和 RAG

```
"听说微调很强，直接上"
```

→ **先穷尽提示词和 RAG**。90% 的需求到这里就解决了。

## 五、微调需要准备什么

### 5.1 数据（最关键）

**质量 > 数量**。

数据格式通常是"输入 → 期望输出"：

```json
[
  {
    "instruction": "把这段话转成客服话术",
    "input": "客户说快递太慢",
    "output": "非常抱歉让您久等了，我帮您查一下物流进度，请稍等。"
  },
  ...
]
```

**数据从哪来**：
- 人工标注（最准，最贵）
- 从历史对话里整理（真实，但需要清洗）
- 用强模型生成（便宜，但要人审）
- 混合使用

**常见问题**：
- 数据不一致（不同人的标注标准不同）
- 有错误答案（模型会学错）
- 覆盖不全（只教了正常情况，没教异常情况）

### 5.2 评估集

**必须留一部分数据不参与训练，用来测试。**

否则你不知道它是真的学会了，还是背下来了（过拟合）。

### 5.3 评估标准

```
❌ "感觉变好了"
✅ "在 200 条测试集上，格式正确率从 72% 提升到 96%"
```

## 六、技术方案（小白版）

### 6.1 LoRA / QLoRA（最主流）

**问题**：全参数微调一个 7B 模型要几百 GB 显存，玩不起。

**LoRA 的思路**：不动原来的参数，只训练一小块"外挂"。

```
原模型（冻结，不动） + 外挂小矩阵（只训这个）
                        ↓
              参数量只有原来的 0.1%–1%
              一张消费级显卡就能跑
```

**类比**：不重写整本书，只在旁边贴便利贴。

**QLoRA**：把原模型再压缩（量化）后训练，显存需求再降一半以上。

### 6.2 其他方案

| 方案 | 说明 |
| --- | --- |
| **全参数微调** | 效果最好，最贵，通常只有大厂做 |
| **LoRA / QLoRA** | 主流，性价比高 |
| **DPO / 偏好对齐** | 让它学会"哪个回答更好" |
| **蒸馏** | 用大模型教小模型 |

### 6.3 现在很多平台支持"托管微调"

```
上传数据 → 平台训练 → 得到一个"你的模型 ID" → 直接调 API
```

省去了搭训练环境的麻烦。适合没有 GPU 资源的团队。

---

## 七、微调的代价

| 成本项 | 说明 |
| --- | --- |
| **数据标注** | 最贵。几千条高质量数据可能需要几万元 |
| **训练算力** | 7B 模型 LoRA 微调，一张 24G 显卡几小时；全参要几百 G |
| **评估迭代** | 训练完不代表能用，要反复评估、调整数据 |
| **维护** | 每次升级基础模型，要重新微调一次 |
| **部署** | 自己需要推理服务；用 API 则要上传模型（很多厂商支持） |

## 八、一个决策流程

```
你需要 AI 做某件事
    │
    ├─ 试试好的提示词（含例子）
    │       └─ 效果够吗？→ 够了，到此为止 ✅
    │
    ├─ 需要它知道你的资料？
    │       └─ 用 RAG ✅
    │
    ├─ 需要它学会一种风格/格式/技能？
    │       └─ 试试少样本（提示词里给 5 个例子）
    │               └─ 够吗？→ 够了 ✅
    │
    └─ 还是不够？
            └─ 微调
                  ├─ 数据够（>500 条）吗？
                  │      └─ 不够 → 先积累数据
                  └─ 能用小模型替代大模型省钱吗？
                         └─ 是 → 这是微调最大价值 ✅
```

## 九、常见困惑

**Q：微调后它会忘掉原来的能力吗？**
会（叫"灾难性遗忘"）。所以数据里要混入一些通用样本，或者用 LoRA 降低影响。

**Q：微调能学新知识吗？**
勉强能"记住"一点，但极不可靠。**知识用 RAG，行为用微调。**

**Q：微调一次要多久？**
LoRA 微调 7B 模型：几十分钟到几小时（看数据量和卡）。
全参微调：几天。

**Q：我能微调 GPT-4 吗？**
闭源大模型一般只提供有限微调接口（指定的数据和格式）。开源模型（Llama、Qwen 等）可以自由微调。

**Q：微调后一定要自己部署吗？**
不一定。很多云平台支持"上传微调数据 → 得到专属模型 API"。

**Q：公司数据会泄露吗？**
看平台条款。**敏感数据不要传给第三方平台训练**，或者用私有部署。

---

## 十、用一句话解释给朋友听

> 「微调就是拿你们的数据再训练模型一遍，让它学会你们的说话方式和做事格式。它不能学到新知识，只能改变行为习惯。而且大多数时候，写好提示词或者接个资料库就够了，不用微调。」
