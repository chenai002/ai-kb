# 04 · 怎么写好提示词

> 记住第 02 篇的结论：**模型是在"续写"你给的东西**。
> 所以提示词不是"命令"，而是"给续写设定一个好的开头"。

---

## 一、一个对比，立刻看懂

**❌ 差的提示词**
```
帮我写个活动方案
```

**✅ 好的提示词**
```
帮我写一个周末亲子活动的方案。
背景：社区图书馆，场地约 100 平，预算 2000 元，参加者是 5-8 岁的孩子和家长，预计 30 组家庭。
要求：
1. 时长 3 小时，包含互动环节
2. 给出流程表和时间安排
3. 列出预算分配
4. 用 Markdown 表格呈现
```

**差别在哪**：好提示词把"模型需要知道但不知道的信息"都给了。

---

## 二、核心原则：把信息补全

模型只知道两件事：
1. 训练时学到的（通用的、旧的）
2. 你这次告诉它的（具体的、新的）

**你告诉得越具体，它越不会"自己编"。**

### 2.1 一个检查清单

写提示词前问自己：

| 问题 | 例子 |
| --- | --- |
| **你是谁 / 你要扮演谁？** | "你是一位有 10 年经验的小学语文老师" |
| **要做什么？** | "写一篇给三年级学生的作文范文" |
| **给谁看？** | "读者是 8-9 岁孩子" |
| **有什么限制？** | "不超过 400 字，不要生僻词" |
| **输出成什么样？** | "分三段，每段有小标题" |
| **什么样的结果算好？** | "要有一个具体的生活场景，不要空喊口号" |

### 2.2 好提示词的四个部分

```
【角色】你是……
【任务】请帮我……
【上下文】背景信息、已有材料、约束条件……
【输出要求】格式、长度、风格、要包含/避免什么
```

> 不需要每次都写满四段，但"任务 + 上下文 + 输出要求"是底线。

## 三、六个实用的技巧

### 技巧 1：给例子（Few-shot）

**比描述更有效的方式是示范。**

```
❌ 请把用户反馈分类成"产品""服务""价格"三类。

✅ 请把用户反馈分类。规则如下：
   反馈："这个按钮点了没反应" → 产品
   反馈："客服态度很好" → 服务
   反馈："太贵了，买不起" → 价格
   现在分类："发货太慢了"
```

**为什么有效**：例子直接告诉模型"你想要的格式和判断标准"，不用猜。

### 技巧 2：让它先想再做（思维链）

```
❌ 这笔订单该不该退款？

✅ 请按以下步骤分析这笔订单：
   1. 列出订单信息（金额、下单时间、是否已发货）
   2. 对照退款政策逐条判断
   3. 给出结论和依据
```

**为什么有效**：把推理过程展开了，模型不容易跳步出错。

### 技巧 3：明确说"不知道就说不知道"

```
如果资料里没有答案，请直接说"资料中没有相关信息"，不要推测。
```

**为什么有效**：模型默认倾向"给个答案"，明确要求能压制这个倾向。

**注意**：这不能完全消除幻觉，只能降低概率。

### 技巧 4：给格式模板

```
请按这个格式输出：
【问题】...
【原因】...
【建议】...
【优先级】高/中/低
```

**为什么有效**：格式约束让输出可预测、可解析（尤其是你后面要用程序处理时）。

### 技巧 5：分步骤，而不是一次性要所有

```
❌ 帮我分析这份财报，总结问题，给出改进建议，再写一份董事会汇报稿。

✅ 第一步：总结这份财报的三个关键问题。
   （确认后）
   第二步：针对第一个问题，给出三条改进建议。
```

**为什么有效**：一次任务越复杂，模型越容易顾此失彼。分步还能让你中途纠正。

### 技巧 6：用分隔符组织长内容

```
请根据下面的<资料>回答问题。

<资料>
（这里放你的长文档）
</资料>

<问题>
这份资料里，退款周期是多少天？
</问题>
```

**为什么有效**：清楚区分"指令"和"材料"，防止模型把资料里的内容当成指令（这也能防一部分提示词注入，见第 12 篇）。

## 四、常见错误

| 错误 | 后果 | 改法 |
| --- | --- | --- |
| 太模糊（"帮我优化一下"） | 模型猜你要什么 | 说清"优化什么方面" |
| 一次要太多 | 每项都做得浅 | 拆成多次 |
| 只说不要什么 | 模型不知道要什么 | 同时给出正面要求 |
| 隐含前提没说明 | 结果不适用 | 把背景写出来 |
| 用抽象词（"专业一点"） | 无法执行 | 换成具体描述（"用行业术语，避免口语"） |
| 长对话里忘了重申要求 | 模型"跑题" | 关键要求放在最后再说一次 |

## 五、几个可以直接套用的模板

### 5.1 写文档

```
你是【角色】。
请写一份【文档类型】，主题是【主题】，读者是【读者】。
必须包含：【要点1】【要点2】【要点3】。
要求：【风格】【长度】【格式】。
不要：【禁忌】。
```

### 5.2 分析问题

```
以下是【材料】：
<材料>...</材料>

请完成：
1. 提炼出 3 个关键问题
2. 每个问题给出原因分析
3. 按影响程度排序
输出为表格。
```

### 5.3 改写润色

```
请改写下面这段文字：
- 保持原意
- 语气更正式
- 删掉重复表达
- 控制在 150 字以内

原文：
<原文>...</原文>
```

### 5.4 角色扮演 / 模拟

```
你是一位严格的面试官，正在面试【岗位】。
请基于我的回答继续追问，一次只问一个问题。
当我答得不好时，指出问题但不要直接给答案。
准备好后请说"请开始"。
```

## 六、提示词工程 ≠ 玄学

很多人以为"会提示词"是天赋。其实它遵循一个简单逻辑：

> **你能把需求描述得多清楚，模型就能做得有多好。**

想想你给同事布置任务的场景：
- 说"帮我搞个方案" → 对方一脸懵
- 说"下周三前给一个面向新客户的推广方案，预算 5 万，重点渠道是短视频" → 对方能干活

**给 AI 写提示词，和给同事交代任务，是一回事。**

---

## 七、常见困惑

**Q：一定要用英文写提示词吗？**
不必。现在主流模型的中文能力很好。但某些复杂推理场景，英文可能略稳。

**Q：提示词写长了好还是短了好？**
**信息密度**更重要。该说的说清楚，不要堆形容词。

**Q：模型说"我理解你的要求了"是真的理解吗？**
只是续写出了这句话。它是否真理解，要看结果。

**Q：为什么同样的提示词，换个时间结果不同？**
模型的随机性（temperature）+ 版本更新。

**Q：需要学"提示词工程"这个职位吗？**
会写提示词是基础能力，不构成独立岗位。真正稀缺的是"能把业务问题拆成 AI 可执行任务"的人。

---

## 八、用一句话解释给朋友听

> 「写提示词就是给 AI 交代任务。你交代得越像给一个聪明但啥背景都不知道的新同事布置工作——说清背景、目标、格式、禁忌——它做得越好。」
