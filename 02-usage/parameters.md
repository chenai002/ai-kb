# 05 · 那些旋钮：温度、长度、采样

> 为什么同样的问题，AI 有时回答得很稳，有时很飘？
> 答案就在几个参数上。这篇讲清楚它们分别控制什么。

---

## 一、先理解"选词"这件事

第 02 篇讲过：模型每次会算出**下一个词的概率分布**。

```
候选：好(45%)  不错(25%)  热(12%)  差(8%)  烂(5%)  其他(5%)
```

**怎么从这些概率里挑一个？** 这就由参数决定。

- 选概率最高的 → 结果稳定、可重复
- 按概率随机选 → 结果多样、有创造性
- 只在靠前的几个里选 → 兼顾

**所有参数本质上都在调这件事。**

---

## 二、最常用的几个参数

### 2.1 temperature（温度）

**控制"随机性"和"创造性"。**

| 值 | 效果 | 适合 |
| --- | --- | --- |
| 0 – 0.3 | 几乎总选最可能的词，稳定、可重复 | 数学、代码、数据提取、分类 |
| 0.7 | 默认值，平衡 | 日常对话、写文章 |
| 1.0 – 1.5 | 更随机，更有创意，也更容易跑偏 | 头脑风暴、写诗、起名 |

**比喻**：温度就像"喝了几杯"。
- 0 度：非常严谨，但可能呆板
- 0.7 度：正常状态
- 1.5 度：放飞自我，说出意想不到的话

**注意**：
- temperature = 0 **也不保证 100% 相同**（底层有浮点误差和并行计算差异），但会很接近。
- 有些模型用 `top_p` 代替 temperature，效果类似。

### 2.2 max_tokens（最大输出长度）

**限制回答的长度上限。**

- 达到上限会被**硬截断**（句子可能断在半截）。
- 不设或设太小，长篇内容会被切掉。
- 它是"输出"的长度，不包含你输入的长度。

**小白容易踩的坑**：
> 你让它写一篇 3000 字报告，但 `max_tokens` 设了 500 → 输出到一半就停了。

**经验值**：1 个汉字 ≈ 1–2 token。要写 1000 字中文，至少留 2000 token。

### 2.3 top_p（核采样）

**只在"概率加起来达到 p 的前几个词"里选。**

```
p = 0.9 时：
  好(45%) + 不错(25%) + 热(12%) + 差(8%) = 90%
  → 只在这 4 个词里挑，"烂"和其他被排除
```

| 值 | 效果 |
| --- | --- |
| 1.0 | 不限制，全部候选 |
| 0.9 | 常用默认，排除极小概率的怪词 |
| 0.5 | 限制更严，更保守 |

**和 temperature 的关系**：两者都在控制随机性，**一般只调一个**。
（OpenAI 官方建议二选一，同时调容易失控。）

### 2.4 top_k

**只从概率最高的 K 个词里选。**

- `top_k = 1` → 等价于"总选最高"，非常死板
- `top_k = 50` → 常规
- 很多 API 不暴露这个参数

## 三、进阶但重要的是几个

### 3.1 frequency_penalty（频率惩罚）

**用过越多次的词，越不想再用。**

**用途**：避免重复。
```
❌ "这个产品非常好，非常好，非常好，非常好"
✅ "这个产品很好用，体验流畅，性价比高"
```

值域一般 -2 到 2，常用 0–1。

### 3.2 presence_penalty（存在惩罚）

**只要出现过，就降低再出现的概率。**

**和 frequency_penalty 的区别**：
- frequency：出现 10 次 → 惩罚 10 份（越用越不想用）
- presence：出现过 → 惩罚 1 份（用过就不想再用）

**用途**：鼓励谈论新话题（写头脑风暴、发散的创意时有用）。

### 3.3 stop（停止词）

**遇到这些字符串就停止生成。**

```json
"stop": ["###", "\n\n用户："]
```

**用途**：
- 防止模型自己"演"出下一轮对话
- 控制输出格式（用 `###` 作分隔）

### 3.4 stream（流式输出）

**一边生成一边返回，而不是等全部算完。**

| | 非流式 | 流式 |
| --- | --- | --- |
| 用户感受 | 等 10 秒，突然出现全部 | 0.5 秒后开始一个字一个字蹦 |
| 首字延迟 | 长 | 短 |
| 总耗时 | 相同 | 相同 |

**为什么 ChatGPT 是"打字机"效果**：就是流式。总时间没变，但**用户感知**好太多。

## 四、怎么选：一张决策表

| 你要做的事 | temperature | top_p | 备注 |
| --- | --- | --- | --- |
| 提取结构化数据（JSON） | 0 | 1 | 要稳定 |
| 代码生成 | 0.2 | 0.95 | 稳定为主 |
| 数学计算 | 0 | 1 | 配合"一步步算" |
| 分类/打标签 | 0 | 1 | 要可复现 |
| 客服问答 | 0.5 | 0.9 | 自然但别跑偏 |
| 写文案 | 0.8 | 1 | 有点创意 |
| 头脑风暴 | 1.0+ | 1 | 越散越好 |
| 翻译 | 0.3 | 0.95 | 忠实原文 |

## 五、其他你可能见到的参数

### 5.1 system prompt（系统提示）

在对话最前面的一段"总规则"，优先级高于用户输入。

```
system: 你是一个只回答技术问题的助手，不知道就说不不知道。
user: 今天天气怎么样？
assistant: 我只能回答技术相关问题。
```

**注意**：它不是"绝对不可违反"的。有些注入攻击能绕过（见第 12 篇）。

### 5.2 seed（随机种子）

指定后，相同输入尽量得到相同输出（需要模型支持）。
用于测试和需要可复现的场景。

### 5.3 response_format（输出格式）

指定输出为 JSON，便于程序解析。

```json
"response_format": { "type": "json_object" }
```

**比在提示词里说"请输出 JSON"更可靠。**

## 六、常见困惑

**Q：temperature 设 0 是不是就绝对准确了？**
不是。它只减少随机性，不解决知识错误和幻觉。

**Q：为什么我对同一个 API 请求两次，结果不同？**
默认有随机性；即使 temperature=0，也可能因浮点与硬件差异有细微不同。

**Q：调 temperature 会不会影响速度？**
基本不影响。速度主要取决于模型大小和输出长度。

**Q：max_tokens 设越大会越贵吗？**
设大不会额外收费，**只有实际生成的 token 才计费**。但设太大会放大"截断风险"。

**Q：流式输出能中途取消吗？**
可以（客户端断开），但**已经生成的部分通常仍会计费**（见第 11 篇）。

## 七、用一句话解释给朋友听

> 「AI 每次回答都是从概率里挑词。temperature 控制它挑得多大胆：0 是只挑最有把握的，1 以上是开始自由发挥。max_tokens 是回答的最大长度。流式是边写边显示，让你感觉更快。」
